Evaluasi Rekayasa Perangkat Lunak

Review Teknis: Mengapa Tidak Menggunakan LLM Wrapper Umum?

Banyak implementasi text-to-SQL modern mengandalkan framework agen generik. Dalam konteks infrastruktur data perusahaan, pendekatan tersebut menimbulkan risiko keamanan dan pemborosan komputasi.

Kelemahan Framework Agen Standar

Implementasi umum sering kali memperlakukan LLM sebagai agen bebas yang mengeksekusi kode secara langsung:

  • Raw write risk: Agen mengeksekusi string tanpa membedakan hak akses baca dan tulis di koneksi database.
  • Token overflow: Dump skema mentah dari puluhan tabel menghabiskan 8.000 hingga 15.000 token per permintaan.
  • Agent loop latency: Rantai berpikir multi-langkah menimbulkan latensi 12 hingga 30 detik untuk pertanyaan sederhana.
  • Audit terpisah: Jejak query dan identitas penanya sering tidak terhubung ke tabel audit terverifikasi.

Pendekatan Rekayasa InsightKit

InsightKit membatasi ruang kendali model dan mengamankan titik eksekusi data secara terisolasi:

  • Koneksi read-only dua lapis: Lapis pertama diatur pada driver database (`default_transaction_read_only`), lapis kedua memblokir keyword terlarang sebelum eksekusi.
  • Penyaringan skema berbasis FK: Skema di-cache secara lokal. Prompt builder hanya menyaring tabel relevan dan relasi foreign key terkait (budget di bawah 3.000 token).
  • Eksekusi deterministik: Gagal query dikoreksi maksimal 3 kali dengan umpan balik terstruktur sebelum mengembalikan status error jelas.
  • Audit append-only: Setiap instruksi query, latensi, user, dan role dicatat ke meta database SQLite internal tanpa fungsi update atau delete.

Arsitektur Eksekusi dan Keamanan

Tidak ada data mentah yang bocor ke luar server. Hanya ringkasan skema dan hasil agregat yang di-mask yang disentuh model bahasa.

1. Isolasi Data Read-Only

Koneksi database memakai user tanpa hak write. Di PostgreSQL diterapkan `default_transaction_read_only`, di SQLite memakai mode URI `mode=ro`, di MySQL diterapkan session read-only.

2. Sanitasi PII Terintegrasi

Regex PII menutupi nomor telepon, NIK 16 digit, nomor kartu debit/kredit, dan alamat email sebelum payload dikirimkan ke model dan sebelum dicatat ke log audit.

3. Kontrol Akses Berjenjang (RBAC)

Tiga role bawaan: Viewer (hanya bertanya dan melihat skema), Analyst (akses metrics tambahan), dan Admin (akses log audit dan refresh skema).

Konektivitas Mesin Data

Dukungan Database Perusahaan

Satu interface tunggal untuk berbagai jenis mesin database relational maupun dokumen analitik.

PostgreSQL SQLAlchemy Async

Dukungan penuh dengan psycopg3 async. Diuji pada dataset transaksi dengan pemaksaan session read-only.

MySQL / MariaDB asyncmy Driver

Koneksi non-blocking murni dengan penegakan transaksi read-only di awal session koneksi.

SQLite aiosqlite Engine

Optimal untuk instalasi lokal, pengujian embedded, serta penyimpanan metadata audit dan skema internal.

MongoDB Motor AsyncIO

Model menghasilkan aggregation pipeline terstruktur. Tahap penulisan seperti $out dan $merge diblokir ketat.

OpenSearch / Elastic SQL REST Plugin

Kueri analitik berbasis SQL di atas klaster pencarian tanpa mengunduh data mentah ke memori agen.

Trino / Presto REST Statement API

Integrasi kueri terdistribusi untuk data lakehouse dan federasi multi-katalog skala besar.
